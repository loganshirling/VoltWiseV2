# VoltWise Project Files

VoltWise project files let you save and reopen the inputs needed to reproduce a local analysis. Use **Save Project** in Data & Rates to download a versioned JSON file, and **Open Project** to select one from your device.

A project archive contains battery profiles and selected profile, saved tariff profiles and active rate schedule, financial assumptions, generation asset settings, site timezone and coordinates, load CSV input and its provenance, and imported solar or wind resource metadata and interval records. Resource source timezones are stored separately from site timezones, and record instants remain canonical UTC. A deliberately unbound measured mode is preserved as an editable state and displays a warning until a resource is reattached or a modeled mode is explicitly selected. Opening a file rebuilds the parsed load dataset from the saved CSV and validates the project structure and resource records before changing the current workspace. A valid file prompts before replacing the current project; canceling or rejecting a file leaves the active workspace unchanged. Save the current project first if you may need to restore it.

Archives are processed in the browser and downloaded or read from the file you choose. VoltWise does not upload them. They may contain household electricity use and detailed site/resource data, so store and share the downloaded file accordingly. To delete a saved project, remove it from the download location or folder where you stored it; VoltWise keeps no separate project-file copy.

An archive is limited to 12 MiB. Embedded load CSV data and each resource CSV are limited to 2 MiB and 35,136 intervals. Projects can configure up to 10 generation assets and 10 imported resource datasets, subject to a **9 MiB aggregate persisted-data budget** measured from the normalized JSON `loadData` and `externalResources` fields. The exact compact archive for a complete quarter-hour 2024 load plus one full-year measured solar and one full-year measured wind dataset was 6,558,485 bytes (6.25 MiB); this leaves room for settings and metadata.

Before accepting a new load or measured-resource import, VoltWise checks the projected compact archive and accepts it only when the archive remains at or below 11 MiB and the aggregate persisted-data fields remain at or below 9 MiB. The 11 MiB import ceiling reserves 1 MiB beneath the 12 MiB file limit for project settings. An over-budget candidate is rejected before replacing active project data or resource attachments. The 12 MiB serialization cap remains in force when saving. File-size checks happen before content is read; domain and interval checks happen before project state changes. Slower or lower-memory browsers may need smaller inputs.

The current writer emits compact JSON with schema version 2. Compact serialization preserves the same JSON keys and validation contract while reducing maximum-combination file size. The first schema version stored the raw load CSV directly and did not record its source. Version 2 groups the CSV with provenance. When an older archive has no resource source timezone, it is migrated as unknown rather than inferred from the installation site's timezone. When a version 1 archive is opened, its CSV and settings are migrated, and the missing load source remains unspecified rather than being guessed. Unsupported future versions, malformed JSON, incomplete project state, invalid timestamps, and corrupt solar/wind records are rejected.

Project archives are separate from analytical JSON and CSV exports. Analytical exports contain results and their assumptions; project archives contain editable inputs for reopening and re-simulation.
