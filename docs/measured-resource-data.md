# Measured solar and wind data

VoltWise accepts measured generation resources as CSV files in the Power Generation step. CSVs must contain a header row, at least two data rows, and the required column names below (header matching is case-insensitive).

| Resource | Required columns | Units |
| --- | --- | --- |
| Solar irradiance | `timestamp`, `ghi_wm2`, `dni_wm2`, `dhi_wm2` | W/m² |
| Wind speed | `timestamp`, `wind_speed_mps` | m/s |

Measurements must be finite and non-negative. Timestamps must be valid, unique, strictly increasing, and evenly spaced. The measured-resource import has its own IANA source-timezone field, independent of the installation site's timezone. The parser accepts ISO timestamps with `Z` or an explicit UTC offset, and local wall-clock timestamps when a valid source time zone is selected. Explicit offsets identify an absolute instant and are never reinterpreted through either configured zone; zone-free timestamps are interpreted in the selected source zone. The parser converts all records to UTC and reports invalid or ambiguous time handling instead of dropping rows.

Each resource CSV is limited to 2 MiB and 35,136 intervals, enough for a complete quarter-hour leap year when the file remains within the byte limit. High-precision records or extra columns can exceed the byte limit even below the row ceiling; VoltWise rejects those files before reading them. The load CSV has the same per-file limits. Combined normalized load/resource data must stay within the project's 9 MiB persisted-data budget, and each new import is checked against the 11 MiB projected compact-archive ceiling. See [project files](project-files.md).

The measured resource interval must match the load interval exactly. Every load timestamp in the simulated period must have a matching resource record; the resource file may cover a larger period. VoltWise does not interpolate or resample missing intervals. Imported data is attached to the selected solar array or wind turbine and shows its interval, covered UTC dates, source time zone, and site time zone. Removing a file leaves the asset in measured mode with an explicit unbound warning; reattach a matching file or select a modeled mode before simulation. VoltWise never silently substitutes synthetic generation after file removal. Resetting generation defaults clears generation assets and their imported resource datasets.

Measured solar uses solar position and panel orientation to estimate plane-of-array irradiance from GHI, DNI, and DHI, then applies array losses, inverter efficiency, and inverter clipping. The ground-reflection term uses a fixed albedo assumption of 0.2. Treat this as an engineering estimate, not a site-calibrated forecast. Measured wind applies hub-height shear and elevation-based air-density corrections to each interval, then the configured turbine power curve, availability, and system loss.

Measured resources support simulation over the imported period. If the load and resource series cover one exact, continuous rolling 12-month period beginning at site-local midnight, with a matching record at every load interval, lifecycle projections replay that same measured period for each projection year. The window ends at midnight on the corresponding calendar date the following year; the site timezone determines its UTC boundaries and expected interval count. Solar hardware capacity degrades, while the irradiance observations stay unchanged; wind measurements and configuration stay unchanged. This is a representative-year scenario, not a weather forecast. Partial-period results remain period totals and are not annualized. See the [G7 measured-resource projection decision](g7-measured-resource-projection-decision.md).

Generation-aware runs provide a separate **Export Period Results (.json)** action. It includes the exact UTC period, generation assets, measured resource records and metadata, battery/tariff/financial settings, interval results, and period cost and energy totals. Lifecycle JSON exports include projection rows only after a complete rolling-year load and resource sequence passes site-timezone, simulation, alignment, and finance validation; those rows represent the same measured period under configured assumptions, not future observed weather.
